# Form Palette adapter migration evidence

This adapter preserves the useful Form Palette and Wrapper experience while delegating headless ordering semantics to DGP Ordering. Canonical contracts replace legacy APIs; they do not justify a thinner integration.

| Legacy behavior | Legacy evidence | Destination | Canonical v1 treatment and preserved outcome | Status | Replacement evidence | Explicit approval |
| --- | --- | --- | --- | --- | --- | --- |
| Form lifetime and persistence | `src/react/inputs/form-context.tsx` | `src/provider.tsx` | The Ordering session is the indefinite value bag; the real Form Palette `Form` receives the live bag with persistence enabled, so values survive field unmounts without a duplicate legacy selection bag. | Verified | `real Form Palette form bridge > retains session-backed values after a Form Palette field unmounts` | Not required—preserve |
| Form core access | `form-context.tsx` `get`, `set`, `snapshot`, `subscribe`, `setFieldError`, and `setErrors` | `FormPaletteFormApi`, `useFormPaletteForm` | Supported `useCore` APIs provide programmatic values, writes, snapshots, subscriptions, errors, and submit. Writes also update canonical Ordering state. | Verified | `exposes programmatic get/set, snapshots, subscriptions, and error channels` | Not required—preserve |
| Real field registration | `wrapper.tsx` `useField` integration | `useOrderingField`, wrapper-bound descriptors | Raw custom components register with the real Form Palette `useField`; value, required, disabled, error, ref, and form ownership remain live. | Verified | `maps wrapper-bound refs, errors, required, and disabled state into a raw custom component` | Not required—preserve |
| Built-in field lifecycle | legacy `InputField` entries | component-bound descriptors | Built-ins render the real Form Palette `InputField`, which owns its supported field lifecycle; no mocked palette substitutes are used in integration tests. | Verified | `uses the real InputField lifecycle to write a text value` | Not required—preserve |
| Descriptor variants | `registry.ts`; `input-registery.ts` | `createFormPaletteInputRegistry` | Registry keys are type plus canonical field variant, exact variants win, unknown variants fall back to `default`, and variants unregister independently. Form Palette render variants are distinct from canonical registry variants. | Verified | `resolves exact variants and falls back to the default descriptor` | Not required—preserve |
| Descriptor adapter channels | `registry.ts`; `wrapper.tsx` | `FormPaletteChangeAdapter`, `OrderingInput` | Descriptors control value, change, and error prop names; normalize host values; map selected option IDs; map action activity; and derive field props without re-owning Ordering behavior. | Verified | `maps values, selected options, descriptor props, variants, and deep templates`; action-trigger test | Not required—preserve |
| Safe templating | legacy Wrapper mini-expression and deep template helpers | `templateFormPaletteProps` | Nested default and host props support safe path interpolation plus `??`/`||` literal fallback. Prototype paths and executable expressions are not evaluated. | Verified | `templates nested props with paths, nullish/or fallbacks, and no evaluation` | Not required—preserve |
| Visible recursive options | Wrapper plus legacy option helpers | `OrderingInput` over Ordering/Core resolved visibility | Visible IDs come from Ordering; recursive filtering retains ancestors, removes hidden descendants, and selection writes are restricted to visible IDs. | Verified | recursive visibility test and selected-option mapping test | Not required—preserve |
| Field and option notices | legacy entry registration `getInputPropsFromField` | default descriptor adapter | Canonical node-targeted notices become field and recursively nested option tags with severity styling. Legacy global-ID and service-ID matching are intentionally absent because they are legacy contract aliases, not behaviors of canonical notice targets. | Verified | `maps canonical field and recursive option notices into Form Palette tags` | Canonical clean break governs representation |
| Built-in catalog and defaults | `src/react/inputs/entries/*` | `createDefaultFormPaletteRegistry` | All supported Form Palette variants are registered, including the `multiselect` type to `multi-select` render mapping, checkbox default/options variants, established useful defaults, and correct scalar/option/recursive/multi capabilities. | Verified | built-in registry metadata test; real text render test | Not required—preserve |
| Built-in UI metadata | legacy entry `ui` declarations and shared InputField metadata | default descriptors | Descriptors expose InputField chrome/layout metadata and variant-specific authoring property metadata while arbitrary JSON-compatible `field.defaults` remain pass-through Form Palette props. | Verified | built-in UI metadata assertions and typed descriptor contract | Not required—preserve |
| Custom registries/components | legacy registry/provider/custom entry | registry factories and `field_binding` modes | Hosts can register, replace, batch-register, resolve, and unregister custom descriptors; raw components use wrapper binding and Form Palette-aware components use component binding. | Verified | variant/custom component tests and wrapper-bound lifecycle test | Not required—preserve |
| Required validation and submission | legacy form-context submit and order-flow provider | `useFormPaletteSubmit`, `useFormPaletteOrderSubmission` | Real Form Palette validation gates snapshot construction. Valid submitted values synchronize to Ordering before Ordering constructs the snapshot. | Verified | `validates required fields through the real Form Palette submit lifecycle` | Not required—preserve |
| Structured Ordering failures | legacy order flow, upgraded canonical failure contract | `src/submission.ts` | Expression and host-configuration failures pass through unchanged and never become valid snapshots. | Verified | `surfaces structured Ordering failures without producing a snapshot` | Not required—preserve |
| Duplicate legacy selection storage and exports | legacy form-context compatibility APIs | canonical Ordering session | Actual selection and trigger outcomes are preserved in Ordering state; obsolete compatibility storage and legacy export names are not reproduced. | Verified | selection and action-trigger bridge tests plus Ordering migration suite | Canonical API/representation clean break |

Visibility, quantity, services, utilities, customer validation, expressions, and snapshot semantics remain owned and tested by Ordering. Studio presentation remains owned by Studio. Those ownership moves are not behavioral retirements.
